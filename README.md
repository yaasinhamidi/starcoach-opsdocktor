# Starcoach OpsDocktor (Liara Deployment Agent)

Diagnosis transport: provider-backed diagnosis uses the pinned Shared SDK adapter (`@starcoach/core-llm@0.5.0`) by default. It requires an explicit request quota: `LIARA_LLM_MAX_ATTEMPTS` (1-1,000), `LIARA_LLM_WINDOW_SECONDS` (1-86,400), and `LIARA_LLM_MAX_CONCURRENT` (1-100). Missing or invalid quota fails closed before transport with a visible `MISSING_CONFIGURATION` status. Both adapters enforce a 1-4,000 completion-token limit and estimated/reported per-request cost caps. The Shared request ledger is in-memory; UNKNOWN attempts retain holds until reconciliation. `LIARA_DIAGNOSIS_ADAPTER=legacy` remains an explicit rollback path. No provider call is enabled without the existing owner opt-in.

An offline, approval-gated recovery MVP for the Starcoach Liara challenge. The runnable slice replays synthetic incident evidence, diagnoses one supported Node startup-entrypoint failure, applies an explicitly approved local fixture repair, verifies the fixture over local HTTP, and simulates separately approved deployment outcomes.

**Status:** offline recovery MVP (`REPLAY + MOCK`); no authenticated Liara access or live deployment has been performed.

## Local requirements

## Quick start

Install the pinned local dependency once with `npm ci --offline --ignore-scripts`, then run `npm test` and `npm run smoke` from this directory. The lockfile resolves `@starcoach/core-llm` from `vendor/starcoach-core-llm-0.5.0.tgz`; no registry request is required. Exact setup steps are in [INSTALLATION.md](docs/INSTALLATION.md). To create a curated standalone copy, run `npm run package:submission -- submission-package-<unique-suffix>`; the exact-file allowlist is `scripts/package-allowlist.json`, and the generated `CONTENT_MANIFEST.json` records sorted paths, byte sizes, and SHA-256 hashes. Verify an existing output with `npm run package:verify -- submission-package-<unique-suffix>`. Neither command overwrites an existing package.

All tests and the ordinary demo are local and offline. Fixture data is synthetic. `npm run liara:readonly-preflight` remains unavailable until the account owner separately approves the exact read scope and configures the local credential; no live Liara result is currently evidenced.

## Offline recovery demo

Run `npm run demo`, then open <http://127.0.0.1:4173>. The Persian RTL flow supports two bounded synthetic repair cases. The startup case diagnoses a missing Node entrypoint and proposes `node missing.mjs` → `node server.mjs`. The port-contract case compares `package.json config.port` with the explicit `liara.json port` and proposes only the matching numeric correction. Plain `EADDRINUSE` remains manual-only. Each patch requires its own simulated repair decision, applies only to a fresh temporary trusted fixture, and then verifies `/healthz` against the known `liara-recovery-v1` artifact marker. This is reported as `LOCAL_HTTP`, separately from `REPLAY` evidence and `MOCK` deployment state. Deployment requires a second decision and verifies the mock candidate ID/version/readiness/current state. Each mutation and Coding Agent handoff is bound to server, run, generation, operation, release, and source-snapshot identity. See the [recording package](docs/DEMO_RECORDING_PACKAGE.md) for a timed five-minute script and alternate branches.

The selected failure is handed to an offline deterministic `FAKE_AGENT` through the strict `RepairTask` 2.0 contract. The offline bounded adapter seam is covered by test doubles but is disabled for authentic backend use until the separate invocation authorization and a trusted OS sandbox are supplied. `AUTHENTIC_AGENT_LOCAL` is not currently verified or selectable. The UI labels approval inputs as simulated. Contract, limits, and reproducible handoff steps are documented in [CODING_AGENT_HANDOFF.md](docs/CODING_AGENT_HANDOFF.md).

For the cross-process acceptance path, run `npm run demo:process`. OpsDocktor starts the fixed local Node worker and shows the `PROCESS_FAKE_AGENT` label plus its worker PID; this proves process transport, not sandboxing or authentic inference. To start directly in the port-contract case, run `npm run demo:port-config-mismatch`. The advisory-only scenarios are available through `npm run demo:port-conflict` and `npm run demo:missing-config`; neither can produce an automatic patch or deployment.

The interface self-hosts Vazirmatn v33.003 Variable WOFF2 and its OFL 1.1 license under `assets/fonts/`. The font is served only from an exact local route with `font/woff2`, while `system-ui` remains the fallback; no CDN, npm, or Google Fonts request is used. Code and evidence blocks use a local monospace stack.

## Liara read-only adapter

`src/liara-readonly.mjs` implements GET-only project details and logs, release listing, and release-filtered log retrieval. The documented PaaS v1 logs endpoint takes `since` but has no release filter. The CLI resolves a release tag through `GET /v1/projects/{name}/releases?page=1&count=100`, then calls its v2 logs route with `releaseId`; v1 logs are always labeled `UNCONFIRMED`. v2 is a CLI contract, not the documented v1 OpenAPI operation, so account availability is unverified. The CLI adds selected team context as the `teamID` query parameter; the adapter requires explicit `teamId` in preflight configuration. Its sanitized evidence separates release-log attribution, exact `missing.mjs` startup-failure identification, and local source-to-release correspondence. The last remains `UNCONFIRMED`; even exact release-scoped logs do not establish that this checkout produced that release. Raw logs, arbitrary paths, secrets, and environment values are not returned.

LIVE READ-ONLY remains off by default. After the account owner separately authorizes this exact read scope, copy `.liara-readonly.example.json` to ignored `.liara-readonly.json`, set `ownerAuthorized` to `true`, and fill in the authorized team, project, release tag, and a `since`/`until` range no longer than six hours. Provide a scoped token only through the local `LIARA_READONLY_TOKEN` environment variable; set `LIARA_READONLY_OWNER_AUTHORIZED=YES` only after authorization. Then run `npm run liara:readonly-preflight`; it performs GET-only project, release, and release-filtered log reads and prints allowlisted evidence. To show the same sanitized evidence in the Persian UI, run `npm run demo:live-readonly` and select its read-only evidence control. Without both authorization gates and local configuration these commands return `UNAVAILABLE` without making API calls. The exact procedure and labels are in [LIARA_READ_ONLY_PREFLIGHT.md](docs/LIARA_READ_ONLY_PREFLIGHT.md). API contract/account permission remains unverified until the owner runs the preflight. These evidence routes are isolated from `MockDeploymentProvider` and cannot deploy.

## Optional LLM diagnosis

Deterministic offline diagnosis remains the default. `src/diagnosis-providers.mjs` routes BoxAPI and OpenRouter diagnosis through the installed Shared SDK adapter by default (legacy is an explicit rollback), with a tested-but-unavailable ChatGPT-plan adapter status, schema/provenance validation, request timeout, request quota and a model-rate-based estimated per-request budget check. Set a provider explicitly and separately opt in with `LIARA_LLM_OWNER_AUTHORIZED=YES`; invoke `/api/diagnose` to analyze current `REPLAY` evidence or `/api/live-diagnosis` to first collect owner-authorized `LIVE_READ_ONLY` evidence. Provider errors are shown beside deterministic fallback results; no other paid provider is selected silently. Keys stay in local environment variables and are never returned by API routes. Two earlier BoxAPI requests returned HTTP 403 (cause `UNKNOWN`; see [the troubleshooting record](docs/BOXAPI_403_TROUBLESHOOTING.md)); no successful real inference is verified, no OAuth flow or account authentication has been performed, and the latest audit made no provider request. The status is `MOCK_TRANSPORT_TESTED` only, not `LIVE_LLM_VERIFIED`. Setup, boundaries, and pricing caveats are documented in [LLM_DIAGNOSIS_PROVIDERS.md](docs/LLM_DIAGNOSIS_PROVIDERS.md).

Current env names are `BOXAPI_API_KEY` + `LIARA_BOXAPI_MODEL` and `OPENROUTER_API_KEY` + `LIARA_OPENROUTER_MODEL` + `LIARA_OPENROUTER_UPSTREAM_PROVIDER`. OpenRouter is pinned to one upstream provider with fallback disabled. Each provider requires owner-verified input/output rates and an explicit per-request cap. Actual cost behavior is not verified; the local estimate is not an account-level hard budget. `openai_chatgpt_plan` deliberately returns `UNAVAILABLE_ADAPTER` until a supported local/open-source OAuth lifecycle is implemented and eligible; identity sign-in alone does not grant inference. See [provider setup and troubleshooting](docs/PROVIDER_TROUBLESHOOTING.md) before enabling either paid adapter.
